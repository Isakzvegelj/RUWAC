# GNOME Remote Login and desktop windows

In Machines → Edit, select Standard / Windows RDP, GNOME Remote Login, or GNOME Desktop Sharing. For Remote Login, RDP Service Login uses the existing service username/password reference. GNOME User Login stores the Linux username and a different Secret Service reference. Set/Replace/Forget applies only to the corresponding password. Switching modes retains saved nonsecret metadata; Windows and Desktop Sharing do not use the second credential. Passwords are not copied from the transport credential.

After an authenticated connection displays GDM, place the caret in the intended field. Open RDP controls → Assisted GNOME Sign-in, verify the selected connection/address/endpoint and login screen, and confirm the field. Send the Linux username, then advance to GDM's password field yourself and repeat confirmation to send the saved Linux password. Submit at GDM yourself. RUWAC does not detect GDM, send Tab/Enter, paste through clipboard or provide an unattended sign-in option. Focus, tab, reconnect, held-input and stale-profile changes cancel pending delivery. Already transmitted input cannot be recalled.

GNOME modes now negotiate the upstream non-AVC RDP Graphics Pipeline. A real authorized Fedora 44 host with GNOME Remote Desktop 50.2/GDM 50.3 passed service authentication, verified same-endpoint RDSTLS handover and rendering of its actual GDM screen. Twelve resolution changes and three fresh-transport reconnects passed. The remote configuration was unchanged; this probe disabled clipboard and sent no Linux credentials. Saved dual credentials and assisted field input remain separate from successful Linux desktop sign-in. Real GDM credential submission, wrong-GDM-password handling and external GNOME clipboard acceptance remain open.

[GNOME's configuration documentation](https://github.com/GNOME/gnome-remote-desktop/blob/main/docs/configuration.md) describes a system-wide transport login followed by user-specific graphical login. The tested installation is GNOME Remote Desktop 50.2/GDM 50.3. [IronRDP's connector configuration](https://docs.rs/ironrdp-connector/0.10.0/ironrdp_connector/struct.Config.html) has one credentials object; its autologon flag populates Client Info with that same credential, not a separately verified GDM mechanism. No supported unattended second-stage mechanism was verified. Ordinary system-wide GDM autologin is a server configuration feature and was not changed.

The connect-time bandwidth patch follows [MS-RDPBCGR Bandwidth Measure Results](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-rdpbcgr/6999bd6a-7eb2-4fba-9e5a-c932596056bf). [GNOME's connect-time state machine](https://github.com/GNOME/gnome-remote-desktop/blob/main/src/grd-rdp-connect-time-autodetection.c) waits for those results. Real host testing now passes this negotiation and the separately implemented graphics/handover stages. Initial service authentication retains CredSSP; redirected sessions use the server-issued RDSTLS credential under verified TLS. Existing cryptographic implementations are preserved.

Use the New window toolbar icon to open an independent saved workspace sharing the daemon. Open the desired RDP/SSH profiles in that window. Each window retains Alt+1–9/0 tab switching. Additional saved layouts have private window identities; `--new-instance --window-id window_HEX` can reopen a known identity. The first window owns the default GUI automation socket. Live RDP transports are not transferred between processes. Releases install the frontend without opening a new owner-desktop copy; restart an older frontend yourself when ready, preserving daemon PTYs.

Machines overlays content by default. Ctrl+K opens search; Escape and tab selection hide the overlay. Preferences provides sidebar width and pinning. Pinning reserves viewport space; an overlay does not. Small allocation drift is ignored for remote dynamic-resize requests. New terminals use the selected user login shell and its configuration; explicit commands and existing sessions are preserved.
