# Terminal and connection usability acceptance

Baseline: published v0.4.1. This increment preserves the existing daemon protocol and persistent processes.

The CLI keeps Ctrl+A. GTK uses Ctrl+Alt+A for local controls so Ctrl+A reaches applications, including a real nested tmux configured with that prefix. The existing shortcut override remains supported. Both clients support lowercase s for horizontal splitting and vertical bar for vertical splitting. CLI status labels accept SGR mouse clicks on the physical bottom row.

New GUI windows and splits pass the selected login-shell argv explicitly, including against an isolated older daemon. New tabs already used that path. Existing shells retain their original startup flags. Tests use generated shell profiles; actual Bash reads the fixture profile and rc. A live view closes when all session shells have ended; it selects a surviving window first. Reattaching ended history remains possible. Closing a GUI leaves the daemon and its live PTYs running.

Current GTK/TUI clients use engine-advertised limits up to 512 rows, 1024 columns and a 262144-cell budget. Running older daemons retain their previous limits and live sessions. Zero-size/unmapped views wait before attaching rather than temporarily imposing a small default size on shared PTYs. Larger physical terminals and smaller simultaneous attachments retain the documented engine bounds and shared sizing policy.

RDP starts with current Dynamic viewport dimensions or its last decoded size. Automatic reconnect also carries forward the last decoded framebuffer dimensions. Queued input from authentication is discarded before the new active transport processes PDUs. An initial-size-aware authenticated loopback peer verifies three reconnects at 1400×868 with no smaller decoded framebuffer after initial settling. This does not prove external Windows application placement or GNOME interoperability.

Native tab context actions target the RDP view; framebuffer right-click stays remote input. Configured disconnected views expose a centered reconnect overlay. Tab titles omit group/protocol text and status is indicated by icons. Connection status describes observed transport state rather than inferred host availability.

About / Support shows version, Apache-2.0, source and a static QR for https://idz.si/bs/ruwac-donate.html. The dialog uses independently implemented GTK widgets; no extension source was copied. The generated QR was independently decoded. Donations use the existing site payment handoff; automatic invoice integration is deferred.

Validation uses generated profiles, owned PTYs, an isolated older daemon, real tmux and native GTK under an owned Mutter compositor. It is automated input, not physical input. The native terminal suite has 15 groups; shell compatibility has four; CLI usability has nine; terminal exit has three; GTK has 116 unit/integration tests. Privacy regression tests use generated values only. Additional RDP clipboard, trust, package and artifact gates are recorded by the qualified release workflow.

Reproduce with configured build.sh --release --test --desktop and release.sh patch. Public source supports cargo test --locked --workspace and cargo test --locked --manifest-path desktop/Cargo.toml from the Rust workspace, followed by the named Python integration scripts against isolated binaries/compositors. Private release configuration and raw host evidence are excluded from publication.

A running GUI keeps its loaded executable after an update. Installing new files does not disconnect it. Restarting the GUI still replaces its RDP transports; persistent background RDP transport/handoff is not implemented. Physical input, current external Windows/Fedora GDM acceptance, dependency advisories, signed Fedora distribution and Weston popup compatibility remain separate gates. This batch does not claim full product completion.

An initial saved-profile fixture created and closed the editor before its first mapping; that synthetic sequence reproduces a GTK 4.22.5 Wayland input-method crash on baseline v0.4.1 and the candidate. Qualification now waits for an allocated dialog before activating Save & Connect, matching an available user action. The candidate also clears editor focus and defers connection opening until the response unwinds. Four mapped editor/connection cycles pass with input methods enabled. No upstream fix for arbitrary unmapped automation is claimed.

Deep legacy Screen/tmux chains can retain an earlier attach size before their clients finish starting. The nesting fixture records that size and drives an explicit physical resize after the chain accepts input; it then verifies exact propagated sizes, byte integrity and the same leaf process. Immediate attach-time size convergence for arbitrary legacy chains is not claimed.

When a real completed PTY has live split siblings, both live clients now close the completed pane through the existing authenticated pane.close method and fetch the repaired canonical layout. They tolerate only the structured STALE_ID response from a competing client's close; other errors propagate. Whole ended sessions and restored history do not trigger automatic pane closure. Closing an exited split has the same history-discard behavior as an explicit pane close. Surviving processes, input routing, viewport expansion and concurrent attachments are qualified by split_exit.py, including an optional older daemon and native GTK-only cases.

The desktop TLS lockfile updates to rustls 0.23.46 following the [upstream release](https://github.com/rustls/rustls/releases/tag/v%2F0.23.46). The four patched rustls advisories and the remaining independent RSA advisory are separate findings; nothing is suppressed.

CLI one-command and detached creation, named session/window/pane commands, Screen control creation and TUI window/split shortcuts now supply the selected login-shell argv explicitly. This also works with preserved older daemons. Raw RPC/JSON request parameters remain literal; existing sessions retain their startup flags. Reattach never resolves a new shell.

For --host named creation, shell-argv discovery runs through the existing verified OpenSSH connection and resolves the shell on that endpoint. The response must contain protocol version zero, an absolute bounded path without controls and exactly the login option. Unsupported endpoint clients fail with an update diagnostic before creation; raw RPC with an explicit remote argv remains available. Both endpoint CLIs should be updated for the named-command behavior. No local shell path is sent as a remote default. The cli_user_shell.py integration suite exercises nine real groups per daemon, including an optional owned loopback SSH server; cli_shell_contract.py covers ten synthetic response cases. These are independent of physical desktop or external-machine acceptance.

The natural-grid extension keeps request and ordinary reply framing at 1 MiB. A client.render request may explicitly set max_response_bytes between that default and 64 MiB; only that reply receives the larger limit. Invalid bounds fail before rendering. Serialization stops at the requested bound; failure returns a correlated LIMIT response without partially writing a frame. Two server permits bound outstanding large-render replies. Updated clients accept larger replies only on their render path. Generic CLI/SSH JSON control remains bounded by the original contract.

Checkpoint schema 6 identifies actual larger saved session, active or retained primary buffers, including a large restored archive viewed at smaller dimensions. Schema 5 remains the writer format when all saved dimensions fit previous limits. Original smaller archives remain readable. An older checkpoint-aware reader rejects an unsupported archive without replacing it. The original per-pane history bounds and 128 MiB checkpoint-file limit remain.

Status drawing and hit testing share a width-aware layout. Clipped labels have stable target ranges; the active window remains visible and hidden-window arrows select adjacent hidden targets. Dedicated labels receive space even when session names or diagnostics are long. Unicode width, combining marks and control filtering remain enforced. Natural-grid tests use generated data and real PTYs; native tests require an explicitly owned large virtual Wayland display and verify actual pixels and kernel sizes. These do not prove physical input or external RDP acceptance.

New Dynamic RDP connections wait for 100 ms of stable allocation before credential lookup or network startup. The wait is bounded at 15 seconds; unavailable layout requires an explicit retry. Selected tabs use their viewport, new background tabs use the allocated TabView, and hidden reconnects use their last decoded size. Disconnect, changed settings/profile or leaving Dynamic mode cancel a pending request. Starting the worker does not later steal focus or clipboard ownership. Fixed/local-scaled modes retain their established initial-size behavior.

The RDP-NATIVE-INITIAL-SIZE case in rdp_clipboard.py requires --honor-client-size and an owned compositor. It drives native profile Save & Connect at 1400×900, 1600×1000 and 1100×700 window sizes, then verifies every decoded desktop size against the settled viewport. It also cancels an IPC-opened request before a transport exists and completes a new background connection without affecting neighboring transports, selection or clipboard. The generated peer supplies actual bitmap updates; the full-desktop cadence counter is not required because its initial bitmap region can be smaller than the negotiated desktop. These results qualify initial desktop dimensions, not external application placement or physical input.
