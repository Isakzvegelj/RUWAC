# ADR — retain the engine; integrate native CLIPRDR and machine metadata

Accepted for the 2026-10-11 increment. Preserve the existing daemon-owned PTYs, canonical alacritty grid, binary split tree, ratios, zoom, bounded generation-checked history and same-UID Unix protocol. GTK/RDP dependencies remain optional and outside the daemon. No competing multiplexer or external RDP viewer is introduced.

Use IronRDP's existing connector, active-session decoder and CLIPRDR state machine. Use ironrdp-cliprdr-format for PNG/DIB conversion. Keep network/decode work on connection workers and PNG/text conversion on bounded completion workers. Latest framebuffer state is coalesced per connection; GUI disconnect clears the previous surface. Transient reconnects invalidate clipboard generations, modifier state and stale queues. Authentication/TLS failures remain visible and fail closed.

FocusBroker is the single metadata ownership authority. A remote offer records tab, format, generation and focus epoch at worker arrival. Only an active eligible offer can request data automatically. Inactive offers remain metadata and do not promote merely because focus later changes. Explicit receive is required for cached offers. Local copy, policy change, disconnect or tab switch invalidates completion. GDK providers published by that tab are excluded from re-advertisement to prevent echoes.

Remote format data is requested asynchronously, with one in-flight request/decode per view and a five-second response deadline. Timeout disconnects rather than reusing the response slot, because CLIPRDR format-data responses carry no application request ID. GDK delayed rendering has a five-second deadline, bounded chunks and owner/focus checks before and after reads. Binary payloads never enter daemon JSON. SVC fragment lengths and cumulative sizes are checked before library reassembly can allocate beyond the image cap. The UI bridge has 16 events and a 64 MiB aggregate payload budget; overflow fails closed.

Text is capped at 1 MiB UTF-8; UTF-16LE is validated for termination, surrogate correctness, NUL and decoded size. Images are capped at 64 MiB encoded/decoded and 4096 pixels per dimension. Prefer registered PNG by name, then DIBV5, DIB, Unicode text. PNG/DIBV5 preserves alpha; classic DIB transfers RGB and loses transparency. Unsupported file/HTML formats are not advertised.

Desktop CLIPBOARD, PRIMARY and the internal Screen buffer remain distinct. Internal GtkTextView selection is still detached from automatic PRIMARY participation. PRIMARY notifications cancel only an active PRIMARY read, not unrelated RDP clipboard work.

Machine metadata uses full group paths and endpoints, rather than leaf names as unique identity. Explicit Remmina preview reads a bounded regular file without following symlinks, imports allowlisted nonsecret fields, and leaves the source untouched. The owned store uses 0700 directory/0600 files, bounded schema and atomic replacement. No credentials, clipboard bodies or owner-library paths enter reports.

Physical GNOME keyboard layouts, AltGr, touchpad gestures, IME and PRIMARY remain unqualified; the owned Weston compositor does not provide PRIMARY. No authorized external Windows or GNOME RDP endpoint was designated, so those host interoperability and physical-desktop gates remain blocked. Dynamic remote resolution/reactivation, panning a desktop larger than the native-pixel viewport, file/HTML clipboard transfer, agent attachment acknowledgement and qualified RPM distribution remain open. In-memory terminal sessions survive client exit, but not daemon or host failure. General abrupt-child termios recovery remains unqualified beyond the owned Bash/job-control regression. The machine library currently imports nonsecret metadata and opens endpoints; a full profile editor and Secret Service management UI are still needed. Product distribution licensing remains unresolved before binary packaging.
