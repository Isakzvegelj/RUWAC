# RUWAC component provenance

The existing engine remains the foundation. No broad market evaluation, replacement repository, cmux-tui integration or RustConn source import was performed in this increment. RDP glue, the broker bridge and machine sidebar are original RUWAC code.

The optional workspace reuses IronRDP 0.17.0, ironrdp-tokio 0.10.0, ironrdp-cliprdr 0.7.0 and ironrdp-cliprdr-format 0.2.0. The disposable test server is ironrdp-server 0.13.0 and is a development dependency, not a product runtime backend. All declare MIT OR Apache-2.0. GTK/libadwaita bindings remain 0.11.5/0.9.2. Native TLS uses system trust with explicit optional CA support. The locked metadata inventory records transitive license declarations; those declarations do not choose RUWAC's product distribution license.

API provenance: [official IronRDP source](https://github.com/Devolutions/IronRDP), [CLIPRDR 0.7.0 documentation](https://docs.rs/ironrdp-cliprdr/0.7.0/ironrdp_cliprdr/). Existing clipboard state machines and converters were integrated instead of reproducing their protocol. No FreeRDP fallback is justified by the current evidence.

Physical GNOME keyboard layouts, AltGr, touchpad gestures, IME and PRIMARY remain unqualified; the owned Weston compositor does not provide PRIMARY. No authorized external Windows or GNOME RDP endpoint was designated, so those host interoperability and physical-desktop gates remain blocked. Dynamic remote resolution/reactivation, panning a desktop larger than the native-pixel viewport, file/HTML clipboard transfer, agent attachment acknowledgement and qualified RPM distribution remain open. In-memory terminal sessions survive client exit, but not daemon or host failure. General abrupt-child termios recovery remains unqualified beyond the owned Bash/job-control regression. The machine library currently imports nonsecret metadata and opens endpoints; a full profile editor and Secret Service management UI are still needed. Product distribution licensing remains unresolved before binary packaging.
