## Maximum-capacity process metadata transport — 2026-10-11

Compiled package 0.1.20 fixes a reproduced process-monitor transport failure. On the published predecessor, 100 actual daemon-owned panes with permitted Unicode labels and long working directories produced 1,049,685 serialized row bytes, exceeding the 1 MiB frame limit and closing `job.list`'s connection. The new daemon caps each metadata result at 64 KiB using actual serialized UTF-8 row sizes, with reserved metadata overhead. The requested `limit` remains an upper bound of 100; the returned `next_offset` advances by the rows actually emitted. Individual fields and the global 128-pane cap remain bounded. A membership token fingerprints the sorted stable IDs, not display names or elapsed process values. The token is an opaque same-daemon pagination consistency check, not an authentication or cryptographic proof.

The native worker now consumes every page until the cursor finishes, with at most 128 requests, at most 128 unique typed pane IDs, valid advancing offsets and exact final counts. It checks the membership token and total across pages and rejects incomplete or conflicting collections before changing the displayed monitor state. The next poll retries after an observed membership change. Older daemons without a membership field retain strict cursor/count/duplicate-ID guards. Process values are sampled while pages are read; this is not an atomic snapshot of continuously changing foreground processes. API transport pages and the native 50-row display pages are separate.

Three real acceptance groups pass. The full 128-pane fixture creates actual programs in a long Unicode directory, measures the raw Unix socket framing, consumes every stable ID without repetition, keeps the same connection usable and verifies unchanged daemon revision and argument exclusion. Native GTK handlers visit 50/50/28 displayed rows, find the last-window target across the full collection and jump to its exact persistent pane without changing the child PID. An actual owned pane closure changes membership and returns STALE_ID for its target. Four additional production-client unit tests use a synthetic owned IPC peer: more-than-two-page compatibility without a membership field, changed membership, duplicate identities, and stalled cursor/incomplete count rejection. These synthetic negative peers do not claim real daemon concurrency or physical input. Existing headless, native, resumable SFTP, encrypted-key, authorized Fedora file, authenticated local RDP/clipboard/display and SSH GUI regressions repeat on the stamped artifacts.

The new full-capacity collection contains 1342778 unpaged row bytes across 22 wire pages; largest complete reply is 63171 bytes. Observed page latency median is 20.18 ms and maximum 29.80 ms for one local fixture run, not an idle-qualified 30-trial benchmark. Metadata retains bounded commands, directories and labels; full command arguments and environment remain excluded. The page budget leaves IPC headroom for normal correlation IDs; this test does not qualify every adversarial request-ID shape or every other API response. General protocol fuzz/soak remains open.

## Persistent SFTP resume and encrypted SSH keys — 2026-10-11

Compiled package 0.1.20 preserves the headless engine and adds durable native SFTP transfer jobs. **Pause transfer** retains a private partial; **Pending transfers…** lists the endpoint's jobs and offers explicit Resume or Discard. Every native upload/download uses this journal. Resume verifies the original authenticated host key, profile binding, source metadata and complete source digest, then compares the retained partial prefix before appending. It verifies the complete staged SHA-256 and original destination before commit. Changed source, destination, host key, profile, symlink, partial prefix or permissions are refused while existing data is preserved. Profile edits keep affected jobs visible with disabled actions until original settings are restored.

Overwrites preserve the reviewed original in a unique remote backup until verified commit cleanup. The commit phase is journaled before renames. A reconnect recovers a completed rename whose reply was lost, restores an original backup if the partial was not delivered, or finishes cleanup of an already delivered file. Discard requires the original host identity for remote mutations and recovers an interrupted original backup before removing owned partials. The journal uses owned nonsymlink 0700 directories, single-link 0600 records, atomic write/fsync/rename, bounded typed IDs, 32 KiB records, at most 128 jobs and 32 GiB files. Stable per-job lock inodes prevent competing workers from splitting ownership across a recreated lock. Completed local journal removal is directory-synced.

The profile editor now provides a separate SSH key passphrase reference and Set/replace/Forget controls backed by existing Secret Service. Only the reference is saved in metadata; the private entry clears after storage. Native SFTP supplies the retrieved passphrase to libssh2 and wipes its key/passphrase buffers after authentication. The ordinary SSH terminal retains OpenSSH's existing key/agent behavior. No graphical dependency was added to the daemon or CLI, and no new runtime or test dependency was introduced.
