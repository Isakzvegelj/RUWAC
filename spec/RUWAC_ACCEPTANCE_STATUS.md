## Maximum-capacity process metadata transport — 2026-10-11

A membership token fingerprints the sorted stable IDs, not display names or elapsed process values. ## Persistent SFTP resume and encrypted SSH keys — 2026-10-11

Compiled package 0.1.21 preserves the headless engine and adds durable native SFTP transfer jobs. **Pause transfer** retains a private partial; **Pending transfers…** lists the endpoint's jobs and offers explicit Resume or Discard. Every native upload/download uses this journal. Resume verifies the original authenticated host key, profile binding, source metadata and complete source digest, then compares the retained partial prefix before appending. It verifies the complete staged SHA-256 and original destination before commit. Changed source, destination, host key, profile, symlink, partial prefix or permissions are refused while existing data is preserved. Profile edits keep affected jobs visible with disabled actions until original settings are restored.

Overwrites preserve the reviewed original in a unique remote backup until verified commit cleanup. The commit phase is journaled before renames. A reconnect recovers a completed rename whose reply was lost, restores an original backup if the partial was not delivered, or finishes cleanup of an already delivered file. Discard requires the original host identity for remote mutations and recovers an interrupted original backup before removing owned partials. The journal uses owned nonsymlink 0700 directories, single-link 0600 records, atomic write/fsync/rename, bounded typed IDs, 32 KiB records, at most 128 jobs and 32 GiB files. Stable per-job lock inodes prevent competing workers from splitting ownership across a recreated lock. Completed local journal removal is directory-synced.

Only the reference is saved in metadata; the private entry clears after storage. Native SFTP supplies the retrieved passphrase to libssh2 and wipes its key/passphrase buffers after authentication. The ordinary daemon stores terminal-history.json in the private RUWAC directory beneath XDG_STATE_HOME (or the standard home state directory), outside the volatile runtime tree. Custom sockets use a history.json sibling unless RUWAC_STATE_FILE explicitly supplies an existing private durable parent. Checkpoint files and locks are owned, regular, singly linked and mode 0600; parents are owned, nonsymlink and 0700. A separate checkpoint lock prevents two socket targets from owning one archive. Startup rejects and preserves corrupt, unknown-schema, oversized or unsafe state. Loaded graphs validate IDs, membership, layouts, active targets and canonical cell/history shapes before serving restored resources.

Changed state checkpoints on a two-second timer. Disk serialization is buffered in a bounded background worker; monotonic revision ordering prevents an older periodic write from replacing a newer explicit save. Atomic rename and file/directory fsync protect completed checkpoints. The daemon.checkpoint RPC waits for a completed write; normal daemon.stop checkpoints before shutdown. Read-only idle queries do not repeatedly rewrite state. health.persistence reports the last completed revision, pending work and write failure; a failed write preserves the previous completed archive and can be retried after repair of the targeted fixture/configuration.

Each pane retains up to 50,000 canonical history rows or 512 KiB of text; dropped_lines is explicit when truncation occurs. The overall archive has a 128 MiB streaming/read cap. Cell snapshots retain Unicode, wide-cell flags and colors; ended panes disable mouse, bracketed-paste and application-input modes. Internal clipboard registers, raw input, RPC/idempotency logs, argv, client identities and credentials are excluded. This is a private terminal-state file, not an ordinary output/request log; already displayed text may contain sensitive content. Removing an ended pane and checkpointing removes its retained history.

This milestone does not establish the full product as final or qualify stable promotion. A crash can lose changes since the last completed automatic checkpoint; the timer interval plus checkpoint duration is not a zero-loss guarantee. Only the active canonical screen is checkpointed: while an application uses the alternate screen, the hidden primary buffer is not yet retained separately. Restored viewport resizing crops/pads the saved visible cells rather than reflowing historical output. Checkpoint serialization latency and retention at maximum multi-pane load still need broader qualification. Existing older live daemons continue unchanged and gain this feature only on a later owner-controlled restart; no protected session is restarted by installation.
