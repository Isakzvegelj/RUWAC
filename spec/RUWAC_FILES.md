# Native SSH files

Open an SSH machine to create its persistent terminal and in-window Files view. RDP-only machines do not imply an SSH service. Existing SFTP upload/download, verified host keys, Secret Service passwords/encrypted-key references and retained pause/resume journals remain available.

The Files view also offers rsync upload of a file or folder, and download of a selected remote item into a chosen local directory. Select chooses a row without navigating; clicking its directory name opens it. Enter one remote item name before transferring. Rsync requires both endpoints to provide version 3.4 or newer and an SSH key or unlocked agent. Password-only or locked-key connections can use SFTP. Install the Fedora `rsync` and `openssh-clients` packages when needed. No password is placed in argv, environment, clipboard, logs or automation replies.

Rsync detection uses an authenticated fixed remote command. Known-host checking is strict against the same selected trust file, global fallback/config hooks are disabled and UpdateHostKeys is explicitly off. Gateway metadata does not silently become a direct rsync connection: a nonempty unsupported gateway is refused. Paths are separate argv values; no user path enters a `sh -c` command. The NUL-delimited explicit file list preserves spaces, quotes, Unicode, wildcard characters and shell metacharacters as literal names. Source trees reject symlinks, devices and special files.

Each copy goes into an owned private staging directory. The complete regular-file set, byte sizes and SHA-256 values are checked before publication. Basic permission bits and modification times are preserved, without ownership, special permission bits, ACLs or extended attributes. This is a verified staged copy, not a filesystem snapshot of a concurrently changing source. Bounds are 32 GiB total, 10,000 entries, 64 directory levels and 4 KiB paths. UTF-8 paths are required. Hash scans and transport phases have cancellation and time limits; rsync allocations are capped.

Existing destinations are refused by default. The separate rsync replacement checkbox replaces the entire destination, including files absent from the source; it does not merge directories. A verified copy is committed with no-replace rename. Explicit replacement first retains the original as an owned backup, restores it if commit fails, then removes the backup after success. A competing actor or cleanup failure can leave a named backup/staging path for inspection. Portable SFTP does not provide a directory transaction spanning every remote actor or power failure.

Pause transfer pauses SFTP with its existing journal; for rsync it cancels the owned process group, removes owned staging and preserves the destination until commit. Rsync cancellation starts a new copy on retry, and does not reuse the SFTP resume journal. Abrupt client/host crashes can leave staging or a replacement backup; automatic rsync crash recovery and independent-actor/power-loss qualification remain open.

The [upstream rsync manual](https://download.samba.org/pub/rsync/rsync.1) documents secluded arguments, literal file lists, progress and remote-shell parsing. RUWAC uses the established OpenSSH/rsync implementation and its existing SFTP verification adapter; the headless daemon remains independent of these desktop file operations.

## Native rsync files — compiled package 0.2.3

The Files view now includes rsync file/folder upload and download, item selection without directory navigation, real asynchronous byte progress and cancellation. SFTP retains its independent Secret Service authentication and pause/resume journals. Rsync verifies local/remote executable versions through fixed authenticated commands, uses strict selected SSH host trust with UpdateHostKeys disabled, and requires a key or unlocked agent. Unsupported gateway routes and password-only/locked-key rsync authentication fail explicitly; SFTP remains available.

Literal NUL-delimited file lists carry spaces, quotes, Unicode, wildcard characters and shell metacharacters without shell expansion. Copies are staged privately and checked for the exact tree, byte lengths and file SHA-256 before commit. Basic permission bits and modification times are preserved. Symlinks/devices/special files and trees exceeding 32 GiB,10,000 entries,64 levels or 4 KiB UTF-8 paths are refused. Existing destinations require explicit whole-destination replacement; no merge or source deletion is implied. No-replace commit retains and restores the original backup on failure; cancel terminates the owned process group and removes staging before publication.

Six real loopback SSH/rsync groups pass: bidirectional tree integrity, modes/controlled timestamps/empty and read-only directories/literal names/explicit replacement; single files; path/host-key/budget guards; active transfer cancellation preserving the original; an actual SSH capability probe with a generated legacy-version response; and native GTK real copy/cancel callbacks preserving the terminal PID. GTK callbacks run synthetically on an isolated Wayland compositor; native chooser code is compiled, while physical chooser/input qualification remains separate. Independently, three actual authorized Fedora host groups pass folder upload, download and default refusal/explicit replacement. Remote content hashes are independently checked and the generated remote fixture removed.

The normal frozen workflow runs full headless regressions and 61 desktop units, updater/format/lint/workflow/dependency/headless-isolation checks, native terminal/recovery/workspace/API, authenticated loopback RDP text/PNG/200-focus/20-resize, SFTP resume/integrity, dual-login/sidebar/user-shell regressions, the six new native rsync groups, real external SSH/SFTP/rsync, and fresh Windows/Fedora GDM framebuffer probes.
